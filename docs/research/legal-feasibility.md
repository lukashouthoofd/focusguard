# Independent implementation and reverse-engineering boundary

Checked: 2026-11-08. This is a project research note, not legal advice. It uses EU legislation and Belgian FPS Economy guidance for an initial feasibility assessment; it is not a substitute for advice on a particular licence, contract, or release.

## Practical conclusion

It is technically feasible to build an independently implemented focus blocker that competes on the same user-facing functions: schedules, website and app rules, timed locks, and persistent Windows enforcement. Those functions can be implemented using Windows services, browser extensions, hosts or network filters, and OS process APIs without copying Cold Turkey code or accessing its paid features. The repo's chosen starting point is Focuser's separately MIT-licensed code base; see the [alternative audit](open-source-alternatives.md) and [upstream attribution](../upstream-focuser.md).

The legal boundary is the implementation and how information is obtained. Belgian FPS Economy guidance says software copyright protects expression and its arrangement, while underlying ideas and functional constraints can be implemented differently; it also warns that program structure, architecture, interfaces, and other expressive elements may be protected. The safe engineering course is to implement the behavior independently, keep distinct product branding and UI, and not copy Cold Turkey source, decompiled code, architecture, text, artwork, or distinctive interface elements. See [FPS Economy: what software rights do not include](https://economie.fgov.be/en/themes/intellectual-property/intellectual-property-rights/copyright-and-related-rights/copyright/intellectual-property-software/creation-computer-program/what-not-included-software) and [what software copyright protects](https://economie.fgov.be/en/themes/intellectual-property/intellectual-property-rights/copyright-and-related-rights/copyright/intellectual-property-software/creation-computer-program/what-protected-copyright-piece).

## Reverse-engineering scope

Article 5(3) of [Directive 2009/24/EC](https://eur-lex.europa.eu/legal-content/EN/TXT/PDF/?uri=CELEX:32009L0024) permits a person entitled to use a copy to observe, study, or test its functioning, while performing acts they are entitled to perform, to determine the ideas and principles underlying the program. Belgian FPS Economy guidance describes the same observation/study/testing allowance. That supports bounded examination of a lawfully used installation for functional ideas; it is not a general right to reproduce the program or its implementation.

Article 6 is a separate, narrow decompilation exception for information indispensable to interoperability of an independently created program, subject to conditions. It restricts the use and disclosure of information obtained through that exception and excludes use to develop or market a program substantially similar in its expression. This project does not rely on that exception: REA observations are used only to document metadata or high-level behavior, and implementation decisions are derived from public documentation, OS documentation, and independently written code. Static metadata is never presented as runtime proof.

The EU Trade Secrets Directive permits independent discovery and certain study, disassembly, or testing of public or lawfully possessed products where no valid duty limits acquisition. Its contract language matters: [Directive (EU) 2016/943, Articles 3–4](https://eur-lex.europa.eu/legal-content/EN/TXT/?uri=CELEX:32016L0943). The current [Cold Turkey Terms](https://getcoldturkey.com/terms/) (effective 15 October 2026) incorporate an EULA that may be presented during use, state that users must not allow others to evaluate copies, and select Ontario law. The EULA accepted for the already-installed copy is not available in this repository. This project does not determine how those terms interact with EU or Belgian law. Because that question is unresolved, further analysis of Cold Turkey binaries or non-public runtime behavior is outside the current research boundary; continue from public product documentation and operating-system documentation unless counsel advises otherwise.

Do not disable or bypass a paid licence, entitlement check, trial limit, or other technical protection measure, and do not publish tools or instructions whose purpose is to do so. Belgian FPS Economy guidance describes disabling technical protection measures and supplying protection-hacking tools as prohibited: [technical measures for protection of works](https://economie.fgov.be/en/themes/intellectual-property/intellectual-property-rights/copyright-and-related-rights/copyright/copyright-protection-works/technical-measures-protection). The project has not analyzed Cold Turkey licensing or entitlement code and will not use paid-only behavior as a test target.

## Release gate

Before a commercial or broadly distributed release, have Belgian/EU IP counsel review the intended reverse-engineering record, the applicable Cold Turkey terms, any third-party marks, and the final product's code, UI, and marketing. The sources above support an independent implementation strategy but do not establish that every reverse-engineering act or a particular release is lawful.
