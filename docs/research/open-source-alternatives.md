## Evidence notes and limitations

- **Focuser:** Its feature list and platform labels above are README claims; source confirms corresponding code paths exist. The Windows loop is created by the UI app, so process termination or a crash stops enforcement until another launch. Browser-only URL/path patterns depend on the extension. The scheduled task is a logon launcher, not persistence against termination during a session. No runtime adversarial testing was performed for this comparison.
- **Open Turkey:** README describes four layers and five-second reapplication; source confirms daemon calls and layer implementations, but this audit did not run the daemon on Linux. The hosts implementation uses direct `os.WriteFile` rather than a temp-file/replace transaction. Its root service and sudoers setup make it a Linux architecture reference, not a Windows code base.
- **Lockdown:** The README itself documents limits and the source shows a scheduled task rather than an SCM service. Having a boot task does not prove that enforcement is tamper-resistant or that crash/recovery paths work. The project also includes LAN management and screen/file-sharing features outside this product's needed scope.

## Recommendation for FocusGuard / PublikHQ

Continue from Focuser's MIT-licensed baseline, retaining its required notice and attribution; building the existing schedules, rule model, extension, and UI again would add work without improving Windows enforcement. FocusGuard already derives from the reviewed Focuser revision. Treat Open Turkey as a design reference for service-owned policy reconciliation, not code to port wholesale. Do not fork or copy Lockdown until its licensing is clarified. Independent implementations of common blocker behavior remain the appropriate route where the desired design differs; do not copy proprietary implementation or bypass paid licensing.

For this repository, the main engineering gap is enforcement architecture, not breadth of UI features: move policy ownership and recovery out of the desktop process, then test installer/service behavior in a disposable Windows VM across process termination, restart, sleep/resume, hosts-file contention, and recovery/uninstall. This comparison itself establishes none of those runtime properties.
